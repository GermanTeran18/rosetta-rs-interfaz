# Descripción

La aplicación **simple\_cycpep\_predict** está pensada para muestrear con rapidez conformaciones cerradas de péptidos pequeños restringidos por ciclación de la cadena principal.  Estos péptidos pueden estar compuestos por cualquier mezcla de residuos de aminoácidos L o D, residuos de aminoácidos aquirales, residuos de peptoides o residuos de oligoureas L o D.  Opcionalmente, el usuario puede especificar que las soluciones deben tener un cierto número de enlaces de hidrógeno en la cadena principal.  El usuario también puede exigir disulfuros entre los residuos que forman disulfuros, en cuyo caso se muestrean todas las permutaciones de disulfuros con el mover [[TryDisulfPermutations|TryDisulfPermuationsMover]].  El usuario también puede especificar que ciertas posiciones están entrecruzadas con agentes de entrecruzamiento, en cuyo caso se usa [[CrosslinkerMover]] para colocar los agentes de entrecruzamiento.  A diferencia del muestreo que realiza la aplicación [[Abinitio-Relax|abinitio-relax]], este muestreo es _independiente_ de fragmentos; es decir, no se requiere ninguna base de datos de estructuras conocidas.

# Líneas de comandos de ejemplo

Un ejemplo de invocación de esta aplicación por línea de comandos sería:

```
/my_rosetta_path/main/source/bin/simple_cycpep_predict.default.linuxgccrelease -cyclic_peptide:sequence_file inputs/seq.txt -cyclic_peptide:genkic_closure_attempts 1000 -cyclic_peptide:min_genkic_hbonds 2 -mute all -unmute protocols.cyclic_peptide_predict.SimpleCycpepPredictApplication -in:file:native inputs/native.pdb -out:file:silent output.silent
```

Este protocolo también puede ejecutarse desde la [[compilación minirosetta|minirosetta]] de BOINC, con gráficos, de la siguiente manera:

```
/my_rosetta_path/main/source/bin/minirosetta.boincstatic.linuxgccrelease -protocol simple_cycpep_predict -cyclic_peptide:sequence_file inputs/seq.txt -cyclic_peptide:genkic_closure_attempts 1000 -cyclic_peptide:min_genkic_hbonds 2 -mute all -in:file:native inputs/native.pdb -out:file:silent output.silent -boinc:graphics true -cyclic_peptide:checkpoint_job_identifier job1 &

/my_rosetta_path/main/source/bin/minirosetta_graphics.boincstatic.linuxgccrelease
```

(El primer comando, arriba, lanza el cálculo, y el segundo lanza la ventana de gráficos.  Consulta la documentación de [[minirosetta]] para obtener más información.)

La aplicación también está disponible en forma MPI para muestrear grandes cantidades de conformaciones en paralelo en varios procesadores (posiblemente a gran escala en un clúster de computación de alto rendimiento como la arquitectura Blue Gene/Q).  Se ha escrito un sistema personalizado de distribución de trabajos para permitir una distribución eficiente del trabajo computacional.  En modo MPI hay opciones de línea de comandos adicionales para controlar el sistema de distribución de trabajos de varios niveles.  Un ejemplo de línea de comandos sería:

```
mpirun -np 25 /my_rosetta_path/main/source/bin/simple_cycpep_predict.mpi.linuxgccrelease -cyclic_peptide:MPI_processes_by_level 1 24 -cyclic_peptide:MPI_batchsize_by_level 10 -cyclic_peptide:MPI_output_fraction 0.1 -nstruct 2500 -cyclic_peptide:sequence_file inputs/seq.txt -cyclic_peptide:genkic_closure_attempts 1000 -cyclic_peptide:min_genkic_hbonds 2 -mute all -unmute protocols.cyclic_peptide_predict.SimpleCycpepPredictApplication_MPI_summary -in:file:native inputs/native.pdb -out:file:silent output.silent
```

Consulta la [[Build Documentation]] para obtener detalles sobre la compilación MPI (Message Passing Interface), y la sección MPI más abajo para más información sobre las opciones específicas de MPI.

# Entradas completas

1.  El usuario debe preparar un archivo ASCII (de texto) que especifique la secuencia del péptido.  Este archivo debe consistir en nombres de residuos separados por espacios en blanco (p. ej., ```PHE LYS ARG DLEU DASP DALA TYR ASN```).  El programa lanzará un error si no se le proporciona un archivo así.  _Ten en cuenta que los archivos en formato FASTA **no** son aceptables, ya que no permiten especificar con facilidad aminoácidos no canónicos.

2.  Opcionalmente, el usuario puede proporcionar un archivo PDB de la estructura nativa con la opción **-in:file:native**.

3.  Todas las demás entradas se basan en opciones.  (Consulta la sección MPI, más abajo, para ver opciones adicionales específicas de esa versión.)  Las opciones relevantes para la versión sin MPI son:<br/><br/>
**-cyclic_peptide:sequence_file \<filename\>** Entrada obligatoria.  El archivo de secuencia, descrito arriba.<br/><br/>
**-cyclic_peptide:cyclization_type \<string\>** Entrada opcional.  El tipo de ciclación.  Las opciones actuales son "n_to_c_amide_bond" (el valor por defecto, que establece un enlace amida terminal), "terminal_disulfide" (que cicla un péptido lineal mediante un disulfuro de cadena lateral), "thioether_lariat" (que cicla un péptido lineal mediante la conjugación del SG de una cisteína y el carbono alfa de un grupo acetilo N-terminal), "nterm_isopeptide_lariat", "cterm_isopeptide_lariat" y "sidechain_isopeptide".  Si se usa la opción "terminal_disulfide", la ciclación se realiza mediante un disulfuro que une los dos residuos formadores de disulfuro más cercanos a los extremos N y C (aunque no tienen por qué estar _en_ los extremos).  La opción "terminal_disulfide" puede usarse con la opción "-cyclic_peptide:require_disulfides", en cuyo caso se considerarán combinaciones de disulfuros entre los residuos formadores de disulfuro internos (_es decir_, no terminales).  La opción "terminal_disulfide" _no_ es compatible con las permutaciones cíclicas ni con el muestreo cuasi-simétrico.  Para más información sobre los lariats de isopéptido, consulta la sección correspondiente más abajo.<br/><br/>
**-cyclic_peptide:use_chainbreak_energy \<bool\>** Si es true (el valor por defecto), se usa la energía de rotura de cadena (chainbreak) para imponer la geometría cíclica de un enlace amida N a C durante la minimización.  Si es false, se añaden restricciones en su lugar.  Ten en cuenta que el enfoque de chainbreak permite la rotación de los ángulos phi y psi terminales, mientras que el enfoque de restricciones actualmente no.<br/><br/>
**-out:nstruct \<int\>** El número de estructuras que la aplicación intentará generar.  Como puede que no se encuentren conformaciones cerradas que cumplan los criterios de enlaces de hidrógeno en todos los intentos, el número real de estructuras producidas será menor o igual que este número.<br/><br/>
**-cyclic_peptide:genkic_closure_attempts \<int\>**  Para cada estructura que se intenta, ¿cuántas veces debe intentar la aplicación encontrar una conformación cerrada?  Por defecto, 10,000.  Valores de 250 a 50,000 pueden ser razonables, según el péptido.<br/><br/>
**-cyclic_peptide:genkic_min_solution_count \<int\>**  Para cada estructura que se intenta, la aplicación seguirá buscando soluciones cerradas hasta que se alcance **genkic_closure_attempts** o se haya encontrado este número de soluciones.  En ese momento, elegirá la solución de menor energía del conjunto encontrado.  Por defecto es 1 (toma una solución en cuanto se encuentra una).<br/><br/>
**-cyclic_peptide:cyclic_permutations \<bool\>**  Si es true (el valor por defecto), se usan permutaciones cíclicas aleatorias de la secuencia para evitar los sesgos introducidos por la elección del punto de corte.  (Por ejemplo, si el usuario proporciona "ALA LYS PHE ASP DILE PRO", podríamos probar "PHE ASP DILE PRO ALA LYS" para la primera estructura, "DILE PRO ALA LYS PHE ASP" para la segunda, etc.)  Todas las estructuras se despermutan antes de la salida final para facilitar el alineamiento.<br/><br/>
**-cyclic_peptide:use_rama_filter \<bool\>**  El algoritmo de cierre cinemático usa tres «residuos pivote» para cerrar el loop.  Estos residuos pivote pueden acabar con valores de phi y psi sin sentido.  Si esta opción se establece en true (el valor por defecto), se filtran los residuos pivote de todas las soluciones y se descartan las soluciones con puntuaciones de Ramachandran deficientes.<br/><br/>
**-cyclic_peptide:rama_cutoff \<float\>**  Si la opción **use_rama_filter** es true (el valor por defecto), se descartarán las soluciones cuyos residuos pivote tengan puntuaciones de Ramachandran por encima de este valor.  Por defecto es 0.8 (algo permisivo).<br/><br/>
**-cyclic_peptide:default_rama_sampling_table \<string\>**  De forma predeterminada, el muestreo de torsiones de la cadena principal de los alfa-aminoácidos está sesgado por el mapa de Ramachandran del residuo en cuestión.  Esta opción permite al usuario especificar un mapa de Ramachandran personalizado que se usará para el muestreo (salvo que se use la opción **-rama_sampling_table_by_res** para anular esta opción).  No se usa si no se especifica.  Los mapas personalizados admitidos actualmente son: flat_l_aa_ramatable, flat_d_aa_ramatable, flat_symm_dl_aa_ramatable, flat_symm_gly_ramatable, flat_symm_pro_ramatable, flat_l_aa_ramatable_stringent, flat_d_aa_ramatable_stringent, flat_symm_dl_aa_ramatable_stringent, flat_symm_gly_ramatable_stringent y flat_symm_pro_ramatable_stringent.<br/><br/>
**-cyclic_peptide:rama_sampling_table_by_res \<integer\> \<string\> \<integer\> \<string\> ...**  Esta opción permite al usuario especificar un Ramachandran personalizado para el muestreo, por residuo de aminoácido.  Por ejemplo, "-cyclic_peptide:rama_sampling_table_by_res 3 flat_symm_pro_ramatable 4 flat_d_aa_ramatable_stringent" asignará una tabla simétrica de prolina al residuo 3 y una tabla de d-aminoácido de alta rigurosidad al residuo 4.  No se usa si no se especifica.<br/><br/>
**-cyclic_peptide:use_classic_rama_for_sampling \<bool\>**  Si es true, se usan los mapas de Ramachandran del término de puntuación `rama` para sesgar el muestreo en lugar de los mapas de Ramachandran, más recientes, del término de puntuación `rama_prepro`.  No se recomienda.  Por defecto es false.<br/><br/>
**-cyclic_peptide:min_genkic_hbonds \<int\>**  Este es el número mínimo de enlaces de hidrógeno de la cadena principal que debe tener una solución de cierre considerada provisionalmente para no ser rechazada.  Por defecto es 3.  Si se establece en 0, no se aplica el criterio de enlaces de hidrógeno.<br/><br/>
**-cyclic_peptide:min_final_hbonds \<int\>**  Este es el número mínimo de enlaces de hidrógeno de la cadena principal que debe tener una solución de cierre final tras la relajación para no ser rechazada.  Por defecto es 0 (lo que significa que se informa del número final de enlaces de hidrógeno, pero no se usa como filtro).<br/><br/>
**-cyclic_peptide:total_energy_cutoff \<float\>**  La puntuación total máxima, por encima de la cual se descartan las soluciones.  No se usa si no se especifica (_es decir_, se aceptan soluciones de cualquier energía).<br/><br/>
**-cyclic_peptide:hbond_energy_cutoff \<float\>**  La energía máxima de enlace de hidrógeno, por encima de la cual un enlace de hidrógeno no se cuenta.  Por defecto es -0.25.<br/><br/>
**-cyclic_peptide:do_not_count_adjacent_res_hbonds \<bool\> Al contar enlaces de hidrógeno, ¿se deben ignorar los enlaces de hidrógeno entre residuos adyacentes?  Por defecto es true.<br/><br/>
**-cyclic_peptide:high_hbond_weight_multiplier \<float\>**  Para las partes del protocolo que realizan relajación con un valor de puntuación de enlace de hidrógeno de la cadena principal con mayor peso (véase la descripción del algoritmo, más abajo), este es el factor por el que se aumenta el peso del término de puntuación de enlace de hidrógeno de la cadena principal.  Por defecto es 10.0 (aumento de diez veces).<br/><br/>
**-cyclic_peptide:count_sc_hbonds \<bool\>**  ¿Deben contarse los enlaces de hidrógeno entre cadena lateral y cadena principal como enlaces de hidrógeno de la cadena principal?  Por defecto es false.<br/><br/>
**-cyclic_peptide:fast_relax_rounds \<int\>**  En los pasos del protocolo en los que se invoca la relajación, este es el número de rondas del protocolo [[FastRelax|FastRelaxMover]] que se aplicarán.  Por defecto es 3.<br/><br/>
**-cyclic_peptide:exclude_residues_from_rms \<string\>**  Una lista de residuos, separados por espacios, que deben excluirse del cálculo del RMSD.  No se usa si no se proporciona.<br/><br/>
**-cyclic_peptide:checkpoint_job_identifier \<string\>**  Si se usa esta opción, los trabajos guardarán puntos de control (checkpoints) de sí mismos para que las aplicaciones **minirosetta** o **simple\_cycpep\_predict** puedan interrumpirse y retomarse donde lo dejaron, sin repetir trabajos fallidos ni rehacer trabajos correctos.  La cadena debe ser un identificador de sesión único que sirva para distinguir entre reintentos de la predicción actual y nuevas ejecuciones.  Muy recomendable para trabajos de BOINC.<br/><br/>
**-cyclic_peptide:rand_checkpoint_file \<string\>**  Si se usa la opción **-checkpoint_job_identifier**, esta opción establece el nombre del archivo de checkpoint que se usa para el generador de números aleatorios.  Por defecto es "rng.state.gz" si no se especifica.  Normalmente, solo hace falta especificarla si varios trabajos con checkpoints comparten el mismo directorio de trabajo.<br/><br/>
**-cyclic_peptide:checkpoint_file \<string\>**  Si se usa la opción **-checkpoint_job_identifier**, esta opción establece el nombre del archivo de checkpoint que se usa para llevar la cuenta de qué trabajos se han completado y cuáles quedan por ejecutar.  Por defecto es "checkpoint.txt" si no se especifica.  Normalmente, solo hace falta especificarla si varios trabajos con checkpoints comparten el mismo directorio de trabajo.<br/><br/>
**-cyclic_peptide:require_disulfides \<bool\>**  Si es true, la aplicación intenta formar disulfuros entre todos los residuos formadores de disulfuro, probando permutaciones con el mover [[TryDisulfPermutations|TryDisulfPermuationsMover]].  False por defecto.<br/><br/>
**-cyclic_peptide:disulf_cutoff_prerelax \<Real\>**  Si require_disulfides es true, esta es la energía máxima de disulfuro por enlace disulfuro que se permite antes de la relajación.  Si la energía supera este valor, la solución se rechaza.  Por defecto es 15.0, pero un valor mucho mayor podría ser apropiado.<br/><br/>
**-cyclic_peptide:disulf_cutoff_postrelax \<Real\>**  Si require_disulfides es true, esta es la energía máxima de disulfuro por enlace disulfuro que se permite después de la relajación.  Si la energía supera este valor, la solución se rechaza.  Por defecto es 0.5.<br/><br/>
**-cyclic_peptide:user_set_alpha_dihedrals \<RealVector\>**  Opcionalmente, el usuario puede fijar ciertos diedros de la cadena principal en valores especificados por él.  Esta opción debe ir seguida de una lista de grupos de cuatro números, en los que el primero representa una posición de la secuencia y el segundo, el tercero y el cuarto son los valores de phi, psi y omega, respectivamente.  No se usa si no se especifica.  Ten en cuenta que esto solo funciona para alfa-aminoácidos y peptoides.<br/><br/>
**-cyclic_peptide:user_set_alpha_dihedral_perturbation \<Real\>**  Si se usa la opción **user_set_alpha_dihedrals**, esta es una pequeña perturbación gaussiana que se añade a todos los diedros que se fijaron.  Por defecto es 0.<br/><br/>
**-in:file:native \<pdb_filename\>**  Un archivo PDB de la estructura nativa.  Opcional.  Si se proporciona, se calculará un valor de RMSD para cada estructura generada.<br/><br/>
**-cyclic_peptide:filter_oversaturated_hbond_acceptors \<bool\>** ¿Deben descartarse las conformaciones muestreadas con más del número permitido de enlaces de hidrógeno a un aceptor?  Por defecto es true.<br/><br/>
**-cyclic_peptide:hbond_acceptor_energy_cutoff \<Real\>** Si se filtran las conformaciones con aceptores de enlaces de hidrógeno sobresaturados, este es el umbral de energía de enlace de hidrógeno por encima del cual un enlace de hidrógeno no se cuenta.  Por defecto es -0.1.<br/><br/>
**-cyclic_peptide:sample_cis_pro_frequency \<Real\>** Esta opción controla la frecuencia (entre 0 y 1) con la que se muestrean enlaces peptídicos *cis* para los residuos que preceden a una D- o L-prolina.  Si no se especifica la opción, la frecuencia es 0.3 por defecto; establécela en 0.0 para desactivar el muestreo de enlaces peptídicos *cis*.  Ten en cuenta que esto se basa en la secuencia de entrada y no se recomienda para diseño, salvo que ciertas posiciones estén fijadas como prolina.<br/><br/>
**-cyclic_peptide:angle_relax_rounds \<int\>** Si se usa esta opción, el número especificado de rondas de FastRelax o FastDesign se realiza con ángulos de enlace flexibles.  La energía cart_bonded se establece automáticamente en 0.5 para este paso, y la energía pro_close en 0.0.  El orden de las operaciones es: FastRelax ordinario (si lo hay), FastRelax con ángulos de enlace flexibles (si lo hay), FastRelax con ángulos y longitudes de enlace flexibles (si lo hay), FastRelax cartesiano completo (si lo hay) y una ronda más de FastRelax normal (solo si se especificaron rondas que podrían dar lugar a ángulos o longitudes de enlace no ideales).  El comportamiento por defecto es no tener rondas de relajación con ángulos de enlace flexibles.<br/><br/>
**-cyclic_peptide:angle_length_relax_rounds \<int\>** Si se usa esta opción, el número especificado de rondas de FastRelax o FastDesign se realiza con ángulos de enlace y longitudes de enlace flexibles.  La energía cart_bonded se establece automáticamente en 0.5 para este paso, y la energía pro_close en 0.0.  El comportamiento por defecto es no tener rondas de relajación con ángulos y longitudes de enlace flexibles.  Consulta la nota anterior sobre el orden de las rondas de relajación.<br/><br/>
**-cyclic_peptide:cartesian_relax_rounds \<int\>** Si se usa esta opción, el número especificado de rondas de FastRelax o FastDesign se realiza con minimización completa en el espacio cartesiano.  La energía cart_bonded se establece automáticamente en 0.5 para este paso, y la energía pro_close en 0.0.  El comportamiento por defecto es no tener rondas de relajación en el espacio cartesiano.  Consulta la nota anterior sobre el orden de las rondas de relajación.<br/><br/>
**-out:file:o \<pdb_filename\>** O **-out:file:silent \<silent_filename\>**  Prefijo de los archivos PDB que se escribirán, O nombre del silent file binario que se generará.<br/><br/>

## Opciones adicionales para estructuras entrecruzadas

La aplicación simple\_cycpep\_predict también puede intentar predecir estructuras entrecruzadas con agentes de entrecruzamiento de tres vías como 1,3,5-tris(bromometil)benceno (TBMB), 1,4-bis(bromometil)benceno (paraBBMB) o ácido trimésico (TMA).  Internamente, esto llama a [[CrosslinkerMover]], que también es accesible desde RosettaScripts y PyRosetta.  Se usan opciones de entrada adicionales para especificar qué residuos de L- o D-cisteína están entrecruzados con TBMB o paraBBMB, o qué cadenas laterales con aminas están entrecruzadas con TMA:

**-cyclic\_peptide:TBMB\_positions \<IntegerVector\>** Si se proporciona, estas posiciones se unirán con un agente de entrecruzamiento de 1,3,5-tris(bromometil)benceno.  Deben especificarse 3N posiciones, y cada grupo de tres se unirá.  No se usa si no se especifica.<br/><br/>
**-cyclic\_peptide:link\_all\_cys\_with\_TBMB \<bool\>** Si es true, todos los residuos de cisteína del péptido se unen con 1,3,5-tris(bromometil)benceno.  Debe haber exactamente tres residuos de cisteína para poder usar esta opción, y no puede usarse con la opción "-TBMB\_positions" (_es decir_, representa una alternativa más rápida a esa opción para el caso especial de secuencias con exactamente tres residuos de cisteína).  También es incompatible con "-link\_all\_cys\_with\_paraBBMB" y "-paraBBMB\_positions".  False/no se usa por defecto.<br/><br/>
**-cyclic\_peptide:use\_TBMB\_filters \<bool\>** Si es true, se aplican filtros basados en la distancia entre las cisteínas de TBMB y en restricciones para descartar las soluciones de GenKIC que no pueden entrecruzarse con facilidad.  True por defecto.<br/><br/>
**-cyclic\_peptide:TBMB\_sidechain\_distance\_filter\_multiplier \<Real\>** Un multiplicador del límite de distancia para las cisteínas de TBMB.  Los valores más altos dan un filtrado más permisivo.  Por defecto es 1.0.<br/><br/>
**-cyclic\_peptide:TBMB\_constraints\_energy\_filter\_multiplier \<Real\>** Un multiplicador de la energía de restricciones para las cisteínas de TBMB.  Los valores más altos dan un filtrado más permisivo.  Por defecto es 1.0.<br/><br/>

**-cyclic\_peptide:paraBBMB\_positions \<IntegerVector\>** Si se proporciona, estas posiciones se unirán con un agente de entrecruzamiento de 1,4-bis(bromometil)benceno.  Deben especificarse 2N posiciones, y cada grupo de dos se unirá.  No se usa si no se especifica.<br/><br/>
**-cyclic\_peptide:link\_all\_cys\_with\_paraBBMB \<bool\>** Si es true, todos los residuos de cisteína del péptido se unen con 1,4-bis(bromometil)benceno.  Debe haber exactamente dos residuos de cisteína para poder usar esta opción, y no puede usarse con la opción "-paraBBMB\_positions" (_es decir_, representa una alternativa más rápida a esa opción para el caso especial de secuencias con exactamente dos residuos de cisteína).  También es incompatible con "-link\_all\_cys\_with\_TBMB" y "-TBMB\_positions".  False/no se usa por defecto.<br/><br/>
**-cyclic\_peptide:use\_paraBBMB\_filters \<bool\>** Si es true, se aplican filtros basados en la distancia entre las cisteínas de paraBBMB y en restricciones para descartar las soluciones de GenKIC que no pueden entrecruzarse con facilidad.  True por defecto.<br/><br/>
**-cyclic\_peptide:paraBBMB\_sidechain\_distance\_filter\_multiplier \<Real\>** Un multiplicador del límite de distancia para las cisteínas de paraBBMB.  Los valores más altos dan un filtrado más permisivo.  Por defecto es 1.0.<br/><br/>
**-cyclic\_peptide:paraBBMB\_constraints\_energy\_filter\_multiplier \<Real\>** Un multiplicador de la energía de restricciones para las cisteínas de paraBBMB.  Los valores más altos dan un filtrado más permisivo.  Por defecto es 1.0.<br/><br/>

**-cyclic\_peptide:TMA\_positions \<IntegerVector\>** Si se proporciona, estas posiciones se unirán con un agente de entrecruzamiento de ácido trimésico.  Las posiciones deben tener aminas primarias en la cadena lateral y deben especificarse 3N posiciones.  Cada grupo de tres se unirá.  No se usa si no se especifica.<br/><br/>
**-cyclic\_peptide:use\_TMA\_filters \<bool\>** Si es true, se aplican filtros basados en la distancia entre las cadenas laterales conjugadas con TMA y en restricciones para descartar las soluciones de GenKIC que no pueden entrecruzarse con facilidad.  True por defecto.<br/><br/>
**-cyclic\_peptide:TMA\_sidechain\_distance\_filter\_multiplier \<Real\>** Un multiplicador del límite de distancia para las cadenas laterales unidas por ácido trimésico (TMA).  Los valores más altos dan un filtrado más permisivo.  Por defecto es 1.0.<br/><br/>
**-cyclic\_peptide:TMA\_constraints\_energy\_filter\_multiplier \<Real\>** Un multiplicador de la energía de restricciones para las cadenas laterales unidas por ácido trimésico (TMA).  Los valores más altos permiten un filtrado más permisivo.  Por defecto es 1.0.

## Opciones adicionales para estructuras unidas a metales

La aplicación simple\_cycpep\_predict puede intentar modelar entrecruzamientos mediados por metales, descartando las muestras que no presentan las cadenas laterales de una manera compatible con alguna de varias geometrías de coordinación de metales.  Las cadenas laterales de los residuos de D- o L-histidina, aspartato o glutamato pueden coordinar metales.  Como los metales entrecruzan en la práctica varios residuos, internamente se llama a [[CrosslinkerMover]].  Actualmente se admiten las coordinaciones octaédrica, tetraédrica, plana cuadrada, piramidal cuadrada, plana trigonal y piramidal trigonal.

## Opciones adicionales para aminoácidos N-metilados

**-cyclic_peptide:n\_methyl\_positions \<IntegerVector\>** Una lista de las posiciones del péptido que están N-metiladas.  Las posiciones N-metiladas tendrán su geometría actualizada y usarán mapas de Ramachandran y bibliotecas de rotámeros específicos para aminoácidos N-metilados.

## Opciones adicionales para el muestreo de longitudes y ángulos de enlace

En anillos pequeños y muy restringidos, las conformaciones a las que se accede variando solo los grados de libertad torsionales pueden no representar adecuadamente el conjunto conformacional real.  El 22 de noviembre de 2019 se añadió compatibilidad para muestrear longitudes y ángulos de enlace en macrociclos peptídicos cíclicos N a C.  (Ten en cuenta que todavía no existe compatibilidad para muestrear estos grados de libertad en otros tipos de química de ciclación.)  Para habilitarlo, usa las siguientes opciones:

**-cyclic_peptide:bondlength\_perturbation\_magnitude \<Real\>** El tamaño de la perturbación, en ångström, que se aplicará a las longitudes de enlace de la cadena principal.  0 por defecto (es decir, no se usa si no se especifica.)
**-cyclic_peptide:bondangle\_perturbation\_magnitude \<Real\>** El tamaño de la perturbación, en grados, que se aplicará a los ángulos de enlace de la cadena principal.  0 por defecto (es decir, no se usa si no se especifica.)

Si usas estas funciones, quizá te convenga usar una función de puntuación que tenga activado el término `cart_bonded` (_p. ej._ `ref2015_cart.wts`).

## Opciones adicionales para el muestreo cuasi-simétrico

A veces se quieren muestrear conformaciones de péptidos con simetría cíclica (_p. ej._ simetría c2, simetría c3, _etc._).  La aplicación **simple\_cycpep\_predict** puede hacer muestreo cuasi-simétrico.  Lo hace copiando los valores de torsión de la cadena principal de los residuos perturbables en distintas repeticiones de simetría, y filtrando tras el cierre para asegurarse de que los residuos pivote adopten conformaciones simétricas.  (Consulta la documentación de [[cierre cinemático generalizado|GeneralizedKIC]] para ver los detalles sobre los residuos perturbables y pivote).  Ten en cuenta que esto es _cuasi_-simétrico y no verdaderamente simétrico porque (a) no usa la maquinaria de simetría de Rosetta, y (b) los valores de torsión de la cadena principal pueden desviarse ligeramente de una repetición de simetría a otra, dentro de los límites definidos por el usuario.  Las siguientes opciones controlan el muestreo cuasi-simétrico:

**-cyclic_peptide:require_symmetry_repeats \<int\>** Si se usa esta opción, solo se aceptarán las cadenas principales con simetría cN (o cN/m, si se exige simetría especular).  Por ejemplo, si se establece en 2, solo se aceptarán cadenas principales con simetría c2.  No se usa si no se especifica (_es decir_, sin esta opción no se realiza muestreo cuasi-simétrico).<br/><br/>
**-cyclic_peptide:require_symmetry_mirroring \<bool\>** Si se usa esta opción, solo se aceptan cadenas principales con simetría especular.  Debe usarse con la opción -cyclic_peptide:require_symmetry_repeats.<br/><br/>
**-cyclic_peptide:require_symmetry_angle_threshold \<int\>** El límite, en grados, que se usa al comparar los valores de torsión de la cadena principal para determinar si las repeticiones de simetría son realmente simétricas.  Por defecto es 10 grados.<br/><br/>
**-cyclic_peptide:require_symmetry_perturbation \<int\>** Si se proporciona, es la magnitud de la perturbación que se aplica al copiar los diedros de la cadena principal para el muestreo simétrico.  Permite muestrear conformaciones ligeramente asimétricas.  Por defecto es 0.0 (sin perturbación).

## Opciones adicionales para predecir estructuras de péptidos lariat con enlace isopeptídico

Además de un enlace amida que conecta los extremos N y C, es posible sintetizar péptidos en los que una cadena lateral que contiene una amina forma un enlace amida con el extremo C, una cadena lateral que contiene un carboxilo forma un enlace amida con el extremo N, o dos cadenas laterales forman un enlace amida.  Estas estructuras lariat de una o dos colas también pueden predecirse con **simple\_cycpep\_predict**.  Las opciones relevantes son las siguientes:

**-cyclic_peptide:cyclization_type \<string\>**  Esta opción, mencionada antes, puede establecerse en "nterm_isopeptide_lariat" para un lariat isopeptídico de cadena lateral a extremo N, "cterm_isopeptide_lariat" para un lariat isopeptídico de cadena lateral a extremo C, o "sidechain_isopeptide" para un macrociclo de dos colas unido por un enlace isopeptídico entre cadenas laterales.

**-cyclic_peptide:lariat_sidechain_index \<int\>** Si se especifica un tipo de ciclación lariat (_p. ej._ "nterm_isopeptide_lariat", "cterm_isopeptide_lariat"), este es el residuo que aporta la cadena lateral que se conecta al extremo N o C del péptido.  Si no se especifica, se usa el residuo del tipo apropiado más cercano al otro extremo.

**-cyclic_peptide:sidechain_isopeptide_indices \<int\> \<int\>** Si se especifica el tipo de ciclación "sidechain_isopeptide", estos son los índices de los residuos que se unen mediante un enlace isopeptídico entre cadenas laterales para formar el loop.  Si no se usa esta opción, se usan los residuos de los tipos apropiados que están más alejados entre sí.  Ten en cuenta que deben indicarse exactamente dos índices.

Ten en cuenta que las opciones **-cyclic_peptide:require_symmetry_repeats** y **-cyclic_peptide:cyclic_permutations** son incompatibles con los lariats isopeptídicos.  Ten en cuenta también que la aplicación **simple\_cycpep\_predict** _no_ usa los tipos de residuo GLX, ASX ni LYX.  Los archivos de secuencia y los archivos PDB nativos deben especificar GLU, ASP y LYS, respectivamente.

## Opciones adicionales para predecir estructuras de péptidos lariat con enlace tioéter

Además de un enlace amida que conecta los extremos N y C, es posible sintetizar péptidos en los que una cadena lateral que contiene un tiol forma un enlace amida con un residuo N-terminal que lleva un grupo 2-cloroacetilo (una estrategia popularizada por PeptiDream). Estas estructuras lariat de una cola también pueden predecirse con **simple\_cycpep\_predict**.  Ten en cuenta que el 24 de mayo de 2022 se fusionaron en la rama master de Rosetta varias correcciones de errores para esta función, que solo están disponibles en las versiones del software publicadas después de esa fecha.  Las opciones relevantes son las siguientes:
**-cyclic_peptide:cyclization_type \<string\>**  Esta opción, mencionada antes, debe establecerse en "thioether_lariat" para un lariat tioéter de cadena lateral a extremo N.

**-cyclic_peptide:lariat_sidechain_index \<int\>** Este es el residuo que aporta la cadena lateral que se conecta al extremo N del péptido.  Si no se especifica, se usa el residuo del tipo apropiado más cercano al extremo C.

Ten en cuenta que las opciones **-cyclic_peptide:require_symmetry_repeats** y **-cyclic_peptide:cyclic_permutations** son incompatibles con los lariats tioéter.  Ten en cuenta también que la aplicación **simple\_cycpep\_predict** _no_ usa el tipo de residuo CYX. Los archivos de secuencia y los archivos PDB nativos deben especificar CYS.

## Opciones adicionales para residuos de oligourea o peptoide

No se necesitan opciones adicionales para usar residuos de oligourea o peptoide con las aplicaciones **simple\_cycpep\_predict**.  Basta con incluir los nombres completos de estos residuos en el archivo de secuencia, igual que se haría con un aminoácido canónico o no canónico.

## Otras opciones útiles

Para péptidos mixtos D/L, la opción **-score:symmetric_gly_tables** puede ser útil.  Esta opción simetriza las tablas de Ramachandran y p_aa_pp que se usan para muestrear y puntuar la glicina, de modo que sea igualmente probable que esté en las regiones D o L del espacio de Ramachandran.  Desde el 23 de febrero de 2016, esta opción también simetriza las tablas de glicina que usa el término de energía RamaPrePro (de modo que las funciones de puntuación talaris2013, talaris2014 y beta\_nov15 son todas totalmente simétricas).

# Salida

Esta aplicación genera salida en archivos PDB o en silent files binarios.  Si se usa lo segundo (recomendado), los recuentos de enlaces de hidrógeno y los valores de RMSD respecto a la nativa (si se proporcionó un archivo nativo) están en las líneas ```SCORE``` del silent file.  Además, estos valores se informan en el registro de salida.

La compilación de BOINC también tiene unos gráficos geniales.

# Algoritmo

El algoritmo es el siguiente:

1.  Para cada intento de muestreo, la aplicación genera un péptido lineal con la secuencia dada (permutada circularmente al azar si la opción **-cyclic_peptide:cyclic_permutations** está en true, el valor por defecto).  La conformación inicial se aleatoriza, con el par phi/psi de cada residuo sesgado por el gráfico de Ramachandran de ese tipo de residuo.  Todos los ángulos omega se establecen en 180 grados.
2.  El protocolo de [[cierre cinemático generalizado|GeneralizedKICMover]] (GenKIC) se usa para encontrar conformaciones cerradas (cíclicas) del péptido.  Se elige al azar un residuo como residuo «ancla» (excluyendo los dos residuos de los extremos).  El resto del péptido es ahora un loop gigante que se cerrará con GenKIC.  El primer residuo, el último y un residuo intermedio elegido al azar se seleccionan como residuos «pivote».  GenKIC realiza una serie de muestreos (hasta un máximo especificado con la opción **-cyclic_peptide:genkic_closure_attempts**) en los que:
     - 2a.  Aleatoriza todos los residuos del loop, sesgados por el mapa de Ramachandran.
     - 2b.  Resuelve analíticamente los valores de phi y psi de los residuos pivote para cerrar el loop.  En este paso, el álgebra lineal que se realiza puede producir entre 0 y 16 soluciones.
     - 2c.  Filtra cada solución según los choques internos de la cadena principal, la puntuación de Ramachandran de los residuos pivote (controlada con la opción **-cyclic_peptide:rama_cutoff**), la presencia de aceptores de enlaces de hidrógeno sobresaturados (controlada con la opción **-cyclic_peptide:filter_oversaturated_hbond_acceptors**) y el número de enlaces de hidrógeno de la cadena principal (controlado con la opción **-cyclic_peptide:min_genkic_hbonds**).  Las soluciones que superan todos los filtros se relajan con [[FastRelax|FastRelaxMover]] con un peso de enlace de hidrógeno elevado (establecido con la opción **-cyclic_peptide:high_hbond_weight_multiplier**) y luego se almacenan.  (Ten en cuenta que el usuario puede especificar varias rondas de FastRelax ordinario, FastRelax con ángulos de enlace flexibles, FastRelax con ángulos y longitudes de enlace flexibles o FastRelax cartesiano.  Se aplican en este orden.  Ten en cuenta también que en este paso se puede sustituir FastRelax por FastDesign; consulta la sección sobre diseño más abajo para más información.)
     - 2d.  Repite de 2a a 2c hasta alcanzar el número máximo de muestras o hasta que GenKIC haya almacenado el número de soluciones (que superan los filtros) especificado con la opción **-cyclic_peptide:genkic_min_solution_count**.
     - 2e.  Elige la solución de menor energía, según la función de puntuación con el peso exagerado de los enlaces de hidrógeno.
3.  La solución resultante se relaja entonces con la función de puntuación convencional (con el peso de los enlaces de hidrógeno restablecido a su valor normal).  De nuevo, el usuario puede pedir varias rondas de FastRelax ordinario, FastRelax con ángulos de enlace flexibles, FastRelax con ángulos y longitudes de enlace flexibles o FastRelax cartesiano completo; estas se realizan en este orden.  Si se usa alguna forma de FastRelax que pueda perturbar los ángulos o las longitudes de enlace respecto a los valores ideales, también se añade una ronda final de FastRelax ordinario al final del todo.
4.  Se aplica un filtro final de enlaces de hidrógeno (controlado con la opción **-cyclic_peptide:min_final_hbonds**).
5.  La estructura, si se encuentra una, se escribe en disco, y la aplicación pasa al siguiente intento hasta alcanzar el número de intentos especificado con la opción **-out:nstruct**.

Opcionalmente, el paso 2c puede realizarse con [[FastDesign|FastDesignMover]] en lugar de FastRelax.  Consulta la sección sobre diseño, más abajo, para más información al respecto.

# Modo de diseño

Aunque se concibió originalmente solo para la predicción de estructuras, la aplicación **simple\_cycpep\_predict** también puede diseñar secuencias para cada conformación muestreada con [[FastDesign|FastDesignMover]].  Las opciones específicas del diseño son las siguientes:

**-cyclic_peptide:design_peptide \<Bool\>** Si es true, la aplicación intenta diseñar la secuencia de cada conformación muestreada.  Si es false (el valor por defecto), solo se realiza relajación con la secuencia fija.<br/><br/>
**-cyclic_peptide:allowed_residues_by_position \<String\>** Este es el nombre de un archivo en el que se proporcionan listas de residuos permitidos (nombres completos) para cada posición numerada del péptido.  Cada línea corresponde a una posición, y la primera columna debe ser el índice de la posición (o "DEFAULT" para especificar la configuración predeterminada que se aplica a todas las posiciones no especificadas).  Si una posición no se especifica (y no se da ningún DEFAULT), se supone que las posiciones no especificadas están fijas (<i>es decir</i>, no son diseñables).  Si no se proporciona ningún archivo pero se usa la opción **-cyclic_peptide:design_peptide**, la aplicación diseñará con todos los L-aminoácidos canónicos y sus equivalentes D, excepto metionina y cisteína.  (La glicina también se excluirá por defecto).  Un archivo de residuos permitidos de ejemplo sería:<br/>
```
DEFAULT ALA VAL LEU ILE ASP GLU LYS ARG DALA DVAL DLEU DILE DASP DGLU DLYS DARG
1 VAL LEU ILE DVAL DLEU DILE #Only hydrophobics at this position.
2 VAL THR DVAL DTHR #Only beta-branched at this position.
3 ASP GLU DASP DGLU ARG LYS DARG DLYS #Only charged residues at this position.
4 ASP GLU DASP DGLU ARG LYS DARG DLYS #Only charged residues at this position.
5 ASP GLU DASP DGLU #Only negatively-charged residues at this position.
```
<br/>**-cyclic_peptide:prohibit_D_at_negative_phi \<Bool\>** Si es true, solo se permiten L-aminoácidos en las posiciones de la región de phi negativo del espacio de Ramachandran.  Por defecto es true.<br/><br/>
**-cyclic_peptide:prohibit_L_at_positive_phi \<Bool\>** Si es true, solo se permiten D-aminoácidos en las posiciones de la región de phi positivo del espacio de Ramachandran.  Por defecto es true.<br/><br/>
**-cyclic_peptide:L_alpha_comp_file \<String\>** Un archivo [[aa_composition|AACompositionEnergy]] opcional para sesgar la composición de aminoácidos de los residuos de la región alfa-helicoidal de phi negativo (hélice a derechas) del espacio de Ramachandran.  No se usa si no se especifica.<br/><br/>
**-cyclic_peptide:D_alpha_comp_file \<String\>** Un archivo [[aa_composition|AACompositionEnergy]] opcional para sesgar la composición de aminoácidos de los residuos de la región alfa-helicoidal de phi positivo (hélice a izquierdas) del espacio de Ramachandran.  No se usa si no se especifica.<br/><br/>
**-cyclic_peptide:L_beta_comp_file \<String\>** Un archivo [[aa_composition|AACompositionEnergy]] opcional para sesgar la composición de aminoácidos de los residuos de la región de hebra beta de phi negativo del espacio de Ramachandran.  No se usa si no se especifica.<br/><br/>
**-cyclic_peptide:D_beta_comp_file \<String\>** Un archivo [[aa_composition|AACompositionEnergy]] opcional para sesgar la composición de aminoácidos de los residuos de la región de hebra beta de phi positivo del espacio de Ramachandran.  No se usa si no se especifica.<br/><br/>

Ten en cuenta que la composición global de aminoácidos también puede sesgarse proporcionando un archivo [[aa_composition|AACompositionEnergy]] con la opción **-score:aa_composition_setup_file**, como en otros protocolos.  En el contexto de la aplicación **simple\_cycpep\_predict**, usar cualquier opción de aa_composition activará automáticamente el término de energía aa_composition en la función de puntuación que se utiliza.

# Muestreo a gran escala en clústeres de HPC con MPI (la Message Passing Interface)

Cuando Rosetta se compila con la opción "extras=mpi", la versión compilada de la aplicación **simple\_cycpep\_predict** (bin/simple\_cycpep\_predict.mpi.[os][compiler][release/debug]) tiene algunas funciones adicionales, con opciones adicionales que las controlan.  En modo MPI, la aplicación tiene un sistema de distribución y recogida de trabajos escalable escrito a medida, adecuado para el muestreo en paralelo en sistemas tan pequeños como un portátil o tan grandes como la infraestructura IBM Blue Gene/Q (cientos de miles de CPU en paralelo).  Las opciones de compilación "extras=cxx11thread,mpi" también habilitarán el paralelismo multihilo dentro de un nodo de cómputo y el paralelismo multiproceso con trabajos distribuidos por MPI entre nodos.  Esto se trata en detalle en la sección siguiente.

El sistema de distribución de trabajos consta de un único proceso **director**, un número arbitrario de niveles de procesos **gestores intermedios** que envían información hacia arriba y hacia abajo por la jerarquía, y un gran número de procesos **trabajadores** que realizan realmente el trabajo de muestreo.  (Ten en cuenta que estas capas se llamaban antes "emperor", "master" y "slave", y pueden aparecer así en versiones antiguas de Rosetta.)  Cada nivel de la jerarquía tiene un número de nodos mayor o igual que el de su nivel padre.  El número de nodos de la jerarquía se especifica con la opción **-cyclic_peptide:MPI_processes_by_level**, seguida de una serie de enteros separados por espacios en blanco que representan el número de procesos de cada nivel, empezando por el director y terminando con los trabajadores.  La suma de estos números debe ser igual al número total de procesos MPI lanzados.  Por ejemplo, lo siguiente especificaría un director, 50 gestores intermedios (en un único nivel de gestores intermedios) y 4949 trabajadores, para un total de 5000 procesos (el mismo número que se lanza):

```
mpirun -np 5000 /my_rosetta_path/main/source/bin/simple_cycpep_predict.mpi.linuxgccrelease -cyclic_peptide:MPI_processes_by_level 1 50 4949 ...(other options)...
```

En lo anterior, los trabajadores se asignarían a los gestores de la forma más uniforme posible.  Como la distribución en dos niveles es muy común, con un director que se comunica con N-1 trabajadores (dados N procesos en total), se puede usar la opción **-cyclic_peptide:MPI_auto_2level_distribution** en lugar de la opción **-cyclic_peptide:MPI_processes_by_level** para configurarla.  La opción **-cyclic_peptide:MPI_auto_2level_distribution** no admite valores.

Al inicio de una ejecución, los trabajadores envían solicitudes de trabajos hacia arriba por la jerarquía.  Los trabajos se distribuyen a cada nivel de la jerarquía en lotes, con tamaños de lote controlados por el usuario.  Si los lotes son demasiado pequeños, el riesgo es que los nodos se pasen todo el tiempo solicitando trabajos y respondiendo a solicitudes; si son demasiado grandes, el riesgo es que los trabajadores queden obligados a completar un gran número de trabajos aunque haya otro trabajador libre para hacerlos (<i>es decir</i>, un mal equilibrio de carga).  El número de trabajos por lote en cada nivel de la jerarquía se controla con la opción **-cyclic_peptide:MPI_batchsize_by_level**, seguida de una lista de enteros separados por espacios en blanco.  Debe proporcionarse un valor menos que con la opción **-cyclic_peptide:MPI_processes_by_level**, ya que los trabajadores no pasan lotes de trabajos más abajo en la jerarquía.  Con el ejemplo anterior, podríamos especificar que el director envíe 200 trabajos a la vez a cada gestor, y que cada gestor envíe 2 trabajos a la vez a cada trabajador, con lo siguiente:

```
mpirun -np 5000 /my_rosetta_path/main/source/bin/simple_cycpep_predict.mpi.linuxgccrelease -cyclic_peptide:MPI_processes_by_level 1 50 4949 -cyclic_peptide:MPI_batchsize_by_level 200 2 ...(other options)...
```

El número total de trabajos se controla con la opción **-nstruct**.  También se puede provocar una terminación prematura con la opción **-cyclic_peptide:MPI_stop_after_time \<Integer\>**, especificando un tiempo en segundos.  Si se usa esta opción, pasado el tiempo transcurrido, el director enviará una señal de parada hacia abajo por la jerarquía.  Los trabajadores (slaves) a los que ya se hayan asignado trabajos completarán todos los trabajos que se les hayan asignado, pero no se les asignarán trabajos posteriores.  Esto es útil para el muestreo a gran escala en sistemas que tienen límites de tiempo para los trabajos.

Cuando los trabajos terminan, no se escriben automáticamente, porque podría haber mucha más salida de la que se puede escribir razonablemente en disco.  En su lugar, los trabajadores envían resúmenes de los trabajos hacia arriba por la jerarquía.  Estos se ordenan durante su paso por la jerarquía según un criterio especificado por el usuario con la opción **-cyclic_peptide:MPI_sort_by \<criterion\>**, donde \<criterion\> es uno de **energy**, **rmsd** o **hbonds**.  De forma predeterminada, los valores más bajos van primero en la lista, pero esto se puede cambiar con **-cyclic_peptide:MPI_choose_highest true**.  El nodo director recibe la lista ordenada y luego envía solicitudes hacia abajo por la jerarquía a los nodos de origen solo para el N % superior (según el criterio de ordenación) de las estructuras de salida, que se envían hacia arriba por la jerarquía al director para escribirlas en disco.  La fracción de estructuras que se escribe en disco se establece con la opción **-cyclic_peptide:MPI_output_fraction**, con un valor de 0 a 1.  Así, si quisiéramos hacer 20,000 muestras y luego escribir el 5 % de las estructuras de salida con menor energía de la ejecución del ejemplo anterior, usaríamos:

```
mpirun -np 5000 /my_rosetta_path/main/source/bin/simple_cycpep_predict.mpi.linuxgccrelease -cyclic_peptide:MPI_processes_by_level 1 50 4949 -cyclic_peptide:MPI_batchsize_by_level 200 2 -nstruct 20000 -cyclic_peptide:MPI_sort_by energy -cyclic_peptide:MPI_output_fraction 0.05 ...(other options)...
```

Los detalles del muestreo se controlan con las mismas opciones que se usan en la versión sin MPI (véase arriba).

Ten en cuenta que, en modo MPI, puede haber una cantidad increíble de salida del tracer.  Por comodidad, el director usa un tracer aparte para escribir un resumen de todos los trabajos que se han completado.  Este resumen incluye la energía de cada muestra, el RMSD respecto a la nativa (si se proporcionó una estructura nativa) y una métrica de calidad del embudo (PNear).  Opcionalmente, los valores de RMSD y PNear también pueden calcularse respecto a la muestra de menor energía (en lugar de respecto a una nativa proporcionada por el usuario).  Para habilitarlo, usa la opción **-cyclic\_peptide:compute\_rmsd\_to\_lowest**.  Alternativamente, los valores de RMSD y PNear pueden calcularse respecto al N % de muestras de menor energía.  Para habilitarlo, usa la opción **-cyclic\_peptide:compute\_pnear\_to\_this\_fract xxx**, donde xxx es un valor de 0.0 a 1.0 que representa la fracción de muestras respecto a la cual se debe calcular PNear.

La métrica PNear toma dos parámetros: **lambda**, en ångström, que controla cuán cerca de la nativa debe estar una muestra para considerarse similar a la nativa, y la **temperatura de Boltzmann**, en unidades de energía de Rosetta, que controla cuán alta debe ser la energía de una muestra no nativa para que el embudo no se considere «malo».  Se establecen con las opciones **-cyclic\_peptide:MPI\_pnear\_lambda** y **-cyclic_peptide:MPI\_pnear\_kbt**, respectivamente.  Consulta Bhardwaj, Mulligan, Bahl, *et al.* (2016) *Nature*, in press para obtener más información sobre la métrica PNear.

Opcionalmente, se pueden calcular las áreas de superficie accesibles al solvente de cada muestra y del conjunto ponderado por Boltzmann.  Para habilitarlo, usa la opción **-cyclic\_peptide:compute_ensemble\_sasa\_metrics**.  La SASA polar, la SASA apolar y la SASA total se incluyen en el resumen de salida.

Para recibir solo este resumen como salida en el flujo de salida estándar, usa las opciones **-mute all -unmute protocols.cyclic_peptide_predict.SimpleCycpepPredictApplication_MPI_summary**.  (Esto silencia toda la salida de los procesos que no son el director y la mayor parte de la salida del proceso director, salvo el resumen del final.)  Como generar y gestionar la salida de un gran número de procesos consume ciclos de reloj y de comunicación MPI, se aconseja silenciar la salida innecesaria para obtener un mejor rendimiento.

Ten en cuenta también que los procesos gestores intermedios son opcionales; lo mínimo que se necesita es un nodo director y un único nodo trabajador (aunque esta configuración no tendría ventajas sobre el muestreo con la versión sin MPI de la aplicación).  En un portátil de 4 núcleos, por ejemplo, lo siguiente sería perfectamente válido:

```
mpirun -np 4 /my_rosetta_path/main/source/bin/simple_cycpep_predict.mpi.linuxgccrelease -cyclic_peptide:MPI_processes_by_level 1 3 -cyclic_peptide:MPI_batchsize_by_level 25 -nstruct 1000 -cyclic_peptide:MPI_sort_by energy -cyclic_peptide:MPI_output_fraction 0.05 ...(other options)...
```

Esto repartiría 1000 trabajos entre 3 procesos trabajadores en lotes de 25 trabajos, con comunicación directa entre el director y cada trabajador (es decir, sin gestores intermedios).  Esto no es recomendable en sistemas muy grandes, ya que el director puede verse inundado por demasiadas solicitudes de comunicación de miles de trabajadores, pero es sensato en sistemas pequeños.

## Uso de paralelismo basado en MPI y en hilos en clústeres de HPC

Cuando se compila con las opciones "extras=cxx11thread,mpi", la aplicación **simple\_cycpep\_predict** puede aprovechar tanto el paralelismo basado en procesos (con trabajos distribuidos por MPI) como el paralelismo basado en hilos (con hilos concurrentes que comparten un espacio de memoria y ejecutan trabajos simultáneamente).  La jerarquía descrita en la sección anterior gana un nivel final: un director distribuye trabajos a cierto número de capas de gestores intermedios, que distribuyen trabajos a cierto número de procesos trabajadores, que lanzan cierto número de hilos de trabajo dentro de un nodo para realizar trabajos en paralelo.  La opción de línea de comandos **-cyclic_peptide:threads_per_worker** especifica el número de hilos de trabajo que puede lanzar cada proceso trabajador.  Ten en cuenta que un valor de 1 hace que no se lance ningún hilo de trabajo; en este caso, el comportamiento es idéntico a la distribución de trabajos puramente basada en MPI.  Los valores más altos dan lugar a hilos de trabajo, con la salvedad de que se usarán N-1 hilos como trabajadores, y el hilo restante queda reservado para la comunicación MPI y la gestión de trabajos.  Estos hilos compartirán un espacio de memoria, incluida una única copia de la base de datos de Rosetta cargada por el proceso en memoria (lo que supone un ahorro considerable de memoria en un nodo de HPC con memoria limitada y abundantes CPU).  Dado un clúster de HPC con L nodos, M CPU por nodo y N núcleos por CPU, se recomienda lanzar un total de L procesos (uno por nodo) y M*N hilos por proceso.  Ten en cuenta, sin embargo, que si M*N es grande puede perderse algo de eficiencia respecto al rendimiento puramente basado en MPI; en ese caso, el equilibrio entre el uso de memoria y el rendimiento debe determinar el número de procesos lanzados por nodo y el número de hilos por proceso.

# Problemas conocidos

- En modo MPI, solo se permite la salida en silent file.  Los usuarios deben proporcionar un archivo de salida con **-out:file:silent**.
- El gráfico de Ramachandran de la glicina debería ser completamente simétrico, pero no lo es, ya que se basa en estadísticas del PDB.  (Las estructuras del PDB tienen glicina de forma desproporcionada en la región del espacio de Ramachandran a la que solo ella puede acceder).  Se ha añadido una opción (**-score:symmetric_gly_tables**) para permitir que se use una versión simetrizada del mapa de Ramachandran de la glicina para el muestreo y la puntuación.
- Actualmente no hay muestreo de los valores de omega, aunque pueden desviarse un poco de 180 grados durante la relajación final.  (La excepción es el muestreo de enlaces peptídicos *cis* en las posiciones que preceden a la prolina; por defecto, se muestrean como *cis* el 30 % de las veces, aunque esto se puede controlar con la opción **-cyclic_peptide:sample_cis_proline_frequency**.)
- Actualmente solo se admiten alfa-aminoácidos, aunque en un futuro próximo será posible generalizarlo a cadenas principales arbitrarias.
- Actualmente no hay compatibilidad con ningún tipo de ciclación distinto de la ciclación cabeza-cola de la cadena principal y la ciclación mediada por disulfuro, ni con ningún tipo de entrecruzamiento distinto de los enlaces disulfuro, el ácido trimésico o el 1,3,5-tris(bromometil)benceno.  Estas limitaciones se abordarán en el futuro.
- Al predecir estructuras de péptidos mixtos D/L, es importante usar una función de puntuación simétrica (_es decir_, una en la que las estructuras especulares se puntúen y minimicen de forma idéntica).  Las funciones de puntuación talaris2013, talaris2014 y beta\_nov15 son todas totalmente simétricas cuando se usan con la opción **-score:symmetric_gly_tables**, y totalmente simétricas salvo en la glicina cuando se usan sin la opción.  Las variantes cartesianas de estas funciones de puntuación (talaris2013\_cart, talaris2014\_cart y beta\_nov15\_cart) también son totalmente simétricas, salvo en la glicina.
- De forma similar, la función de puntuación utilizada debe admitir geometría cíclica.  Todas las funciones talaris2013, talaris2014 y beta\_nov15 (además de sus variantes cartesianas, talaris2013\_cart, talaris2014\_cart y beta\_nov15\_cart) admiten geometría cíclica desde el 20 de septiembre de 2016.
